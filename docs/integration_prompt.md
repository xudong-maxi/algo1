# 集成提示词：把 JDPS 算法移植进本地工程

> 用法：把下面「提示词正文」整段发给负责集成的 agent，并让它能访问本地工程和本仓库（`xudong-maxi/algo1`，分支 `claude/bluetooth-handling-d3l8j4`）。

---

## 提示词正文

你要把一个已经验证过的算法模块 **JDPS**（多 subevent 的多普勒 + AGC 相位联合补偿）集成到我的嵌入式工程里。需要做两件事：一是适配工程的接口、数据来源和构建；二是按工程现有的风格整改命名和代码组织。**算法的数学过程和数值行为不允许改变**，改完必须通过回归测试证明这一点。

### 1. 参考材料（来自仓库 xudong-maxi/algo1，分支 claude/bluetooth-handling-d3l8j4）
- `c/jdps.h`、`c/jdps.c`：要移植的 C 实现（C99、float32、无动态内存、流式接口）。
- `c/test/jdps_test.c`、`c/test/complex_type.h`、`c/Makefile`：主机回归测试；`make test` 会调用 Python 生成测试向量 `c/test/vectors.txt`（20 个用例），再逐点对比 C 输出。
- `cs_agc/export_vectors.py`、`cs_agc/algorithms.py`：Python 参考实现和测试向量生成脚本（需要 numpy）。
- `cs_agc/log_replay.py`：实测 log 的解析方式，用来对照「IQ 怎么组织」。
- `docs/multi_subevent_agc_design.md`：算法原理（§2 信号模型，§4 各 Stage，§7 流式结构与复杂度，§9 已确认的硬件条件）。

开始前先把这些文件读完。

### 2. 已确认的系统条件（按这些条件适配，不要再去猜）
- 协议：BLE Channel Sounding，Mode‑2 PBR，随机跳频，72 个信道（ch 2–22、26–76，f = 2402 + ch MHz）。
- 每个 procedure 的跳频表 `ch_idx_list` 中**第 1 项是 mode0，要跳过**，其余 72 项按顺序分到各个 subevent，步数近似均分（例如 25/25/22）。
- 时序：每个 step 测量 565 µs、间隔 150 µs；相邻 subevent 之间**空隙 40 ms**（从上一个结束到下一个开始）。step 时间戳取测量段中心。如果工程里有真实时间戳，优先使用真实值。
- IQ：每条天线路径的输入是**本地 IQ × 远端 IQ（直接相乘，不取共轭）**，按跳频（时间）顺序排列；缺失或无效的 tone 填 0+0j。
- 天线：4 条路径 = 发起端 2 根 × 反射端 2 根（两根天线互相垂直）；path0=(0,0)、path1=(0,1)、path2=(1,0)、path3=(1,1)。
- AGC 按设备设定，每个 subevent 只设一次 → 使用**共享相位模式**（`per_ant_phase = 0`）；速度**4 路统一拟合**（算法本来就是这样）。
- 平台：MCU 128 MHz，带单精度 FPU。AGC + 多普勒补偿处理（不含测距）4 路合计必须 < 60 ms，当前估算约 8.6 ms（K=3）。
- 内存：**任何时刻只能有一路 IQ 在内存里**，但同一路 IQ 可以多次读取。所以必须保留流式调用：每路 `add_velocity` → `solve_velocity` → 每路 `add_phase` → `solve_phase` → 每路 `apply`。
- 复数类型：工程里已有 `complex` 结构体，成员**依次**为 `float r`、`float i`。不要另外定义复数类型。

### 3. 必须保持不变的东西（算法契约）
以下任何一项改动都会改变结果，**禁止修改**。如果你认为某项必须改，先停下来问我。
1. 配对方式：信道号相差 +1、+2 的 step 两两配对，按 (间隔, 低频端 segment, 高频端 segment) 分组；组号公式、配对乘积 `y_hi * conj(y_lo)`（保留幅度加权，不能只取相位）。
2. 配对相位率 `pair_rate` 的计算：频率先减去参考频率（平均信道号），时间先减去 t_ref（平均 step 时间）和各 segment 的平均时间。这样做是为了 float32 精度，不能化简回直接用绝对频率乘绝对时间。
3. 速度搜索：网格范围是 ±(v_max + guard)；旋转因子用复数乘法递推，每 16 个网格点重新归一化一次；指标是「各组和的模」对组、对天线求和；峰值用抛物线插值。
4. 可信度判断：score = (峰值 − μ) / σ，其中 μ = Σ sqrt(π/4·S_g)，σ² = Σ (1 − π/4)·S_g。score < min_v_score，或峰值落在网格最外侧时，速度改为 0；全部输入为 0 时返回 NO_SIGNAL，IQ 保持原样。
5. 多普勒补偿：`exp(+j·4π/c · f_n · v · (t_n − t_ref))`，使用每个 step 自己的频率 f_n（同时补偿距离迁移）；相位先折回 [−π, π] 再算 sin/cos。
6. 相位同步：截距初值只用 segment 内部的配对；`H = Q + Q^H`，对角线先取 2·Re(Q_kk)，再整体设为各行 |H| 之和的最大值（**这个对角线移位不能删，否则 K=2 时幂迭代会振荡**）；幂迭代每步逐元素归一化；结果归一化成 ψ_0 = 0；外层迭代时更新截距。
7. 默认参数：v_max 10、guard 1、步长 0.25 m/s、min_v_score 5、orders 2、幂迭代 8 次、外层 3 轮。

### 4. 可以并且应该按工程风格整改的东西
- 所有标识符（函数、类型、宏、变量、枚举、错误码）改成工程的命名规范，包括前缀、大小写、缩写习惯。
- 文件名、目录位置、头文件包含方式、注释和文档格式（例如 Doxygen 风格、中英文注释），都跟随工程现有代码。
- 错误码改用工程统一的返回值类型；日志、断言、参数检查改用工程已有的宏。
- 数学函数（sinf/cosf/sqrtf/atan2f/rintf/lrintf）如果工程有 CMSIS-DSP 或自己的快速实现，可以替换，但替换后精度必须让回归测试通过。
- 上下文结构体放在哪里、怎么分配（静态、全局、内存池），按工程惯例；用编译宏 `JDPS_MAX_SEG` 等收紧上限以节省内存（例如 subevent 最多 3 个时设为 3，ctx 约 6.5 KB）。
- 调用侧胶水代码：从工程现有的 CS 结果结构里取出跳频表、segment 划分、时间戳，逐路取出本地/远端 IQ 并相乘，然后按流式顺序调用；补偿后的 IQ 交给工程现有的 IFFT 测距流程。速度和 ψ 按工程习惯输出到日志或结果结构。
- 只做与集成有关的改动，不要顺手重构工程里其他代码。

### 5. 工作步骤
1. **调研工程，先不要写代码**：找到并列出这些位置——CS 结果数据结构、跳频表和 mode0 的位置、本地/远端 IQ 的存储和读取方式、step 时间戳或时序参数、现有的多普勒补偿实现（要被替换或绕过）、IFFT 测距入口、`complex` 的定义头文件、命名和错误码规范、构建系统。
2. **给我一份适配方案后等我确认**：包括模块放在哪、改名对照表（原名 → 新名）、调用侧数据流（每一遍从哪里读 IQ、结果写回哪里）、内存预算（ctx 大小加一路 IQ 缓冲）、现有多普勒补偿的处理方式（替换还是开关切换）。**确认后再开始改代码。**
3. 移植并整改 `jdps.h/.c`：只改命名、风格和工程接口，算法逻辑逐行对应原实现。
4. 同步移植主机回归测试：把 `jdps_test.c` 改成调用改名后的接口，保留「只用一块单路 IQ 缓冲区」的调用方式；`test/vectors.txt` 用 `python -m cs_agc.export_vectors` 从本仓库生成，不要手改。
5. 写调用侧胶水代码，接入测距流程，配置开关默认打开新算法（如果工程习惯是先默认关闭，就按工程习惯来，并告诉我）。
6. 在目标板或模拟器上编译；如果可以，用 DWT 周期计数器测量 4 路处理的总耗时。

### 6. 验收标准
- 主机回归测试 20/20 通过，容差不放宽：速度差 < 0.01 m/s，ψ 差 < 0.01 rad，补偿后 IQ 的相对误差 < 1e-3，状态码和可信标志完全一致，score 相对误差 < 1e-3。
- 目标平台编译无新增警告；不使用 malloc；IQ 内存峰值为一路。
- 4 路处理总耗时 < 60 ms（给出实测值或基于实测的估算）。
- 改名对照表完整；被删除或改写的工程原有代码逐一列出原因。
- 如果有实测 log，用本仓库的 `python -m cs_agc.log_replay` 和工程实现分别处理同一份数据，速度、ψ 和测距结果应一致。
